# SPEC.md — Программа мониторинга наличия сети интернет

> Спецификация задачи. Внешняя память для агента — перечитывать при каждой итерации.
> Пайплайн: опрос ✅ → план/спецификация (этот файл) → тесты → изоляция → оркестратор.

## 1. Постановка

Программа непрерывно определяет **текущее состояние интернета** среди 4 состояний и уведомляет пользователя при **смене состояния**. Историю не хранит (только лог переходов).

## 2. Четыре состояния

| ID | Состояние | Определение |
|----|-----------|-------------|
| 1 | Интернет без ограничений | Публичный хост доступен по HTTP, и доступен «запрещённый» хост |
| 2 | Интернет без ограничений с VPN | То же что (1), но обнаружен активный VPN-интерфейс |
| 3 | Белые списки (ограниченный) | «Разрешённые» хосты доступны, «запрещённые» — нет |
| 4 | Интернета нет | Ни одна проверка не проходит |

> Замечание: состояния 1 и 2 отличаются **только** фактом активного VPN. Логика доступности одинаковая.

## 3. Методы определения

### 3.1 Доступность хоста
Для каждого хоста: HTTP/HTTPS GET с `connect_timeout` и `read_timeout`. Считаем доступным, если получили HTTP-ответ (любой 2xx/3xx/4xx — главное, что TCP установлен и сервер ответил). 5xx / network error / timeout → недоступен.

### 3.2 Обнаружение VPN (для состояния 2)
Два независимых признака, считаем VPN активным если выполняется **хотя бы один** (с приоритетом первого):

1. **Наличие VPN-сетевого интерфейса.** Через `psutil.net_if_addrs()` ищем адаптеры с именами, попадающими под паттерны: `TAP`, `TUN`, `Wintun`, `wg`, `OpenVPN`, `vpn` (case-insensitive). Исключаем виртуальные адаптеры Hyper-V/VirtualBox (по имени).
2. **Сравнение внешнего IP.** Запрос к публичному сервису `https://api.ipify.org` (или аналог). Если возвращённый IP не входит в приватные диапазоны RFC1918 и не равен «прямому» IP провайдера (определяется при старте без VPN или задаётся в настройках) — считаем что трафик через VPN.

> A4: «VPN включён, но не работает» — **не различаем**. Если VPN-интерфейс есть, но ни один хост не доступен → состояние 4.

### 3.3 Логика определения состояния (на одну итерацию проверки)
```
allowed_ok   = (хотя бы один разрешённый хост доступен)
blocked_ok   = (хотя бы один запрещённый хост доступен)
vpn_active   = (обнаружен VPN по 3.2)

if not allowed_ok and not blocked_ok:
    state = 4  # интернета нет
elif allowed_ok and not blocked_ok:
    state = 3 if not vpn_active else 3   # белый список (VPN не меняет состояния 3)
elif allowed_ok and blocked_ok:
    state = 2 if vpn_active else 1
else:  # not allowed_ok and blocked_ok — вырожденный случай
    state = 4  # нет ожидаемого белого хоста → считаем нет сети
```

### 3.4 Подтверждение смены состояния (A14)
Состояние считается **подтверждённым**, если оно стабильно держится **N подряд** итераций (дефолт `confirm_count = 2`, настраивается). Единичный провал не переключает состояние.

## 4. Реакция на смену состояния

- **Звуковой сигнал** (Windows): короткий beep / системный звук. Разный звук для «нет сети» (тревога) и «восстановление/улучшение».
- **Уведомление Windows** (toast notification): текст вида «Состояние сети: <название>».
- **Лог-файл** `monitor.log`: запись только при смене состояния: `timestamp | old_state → new_state | детали`. Историю по периодам не храним.

## 5. Конфигурация (настройки)

Выносится в `config.json` / `config.yaml`, рядом с программой. Все значения ниже — дефолтные, редактируемые пользователем.

```yaml
# config.yaml
interval_sec: 6              # A11: интервал проверки, дефолт 6 (в диапазоне 5-7)
connect_timeout_sec: 5       # таймаут установки соединения
read_timeout_sec: 5          # таймаут чтения ответа
confirm_count: 2             # A14: сколько подряд подтверждений для смены состояния

hosts:
  allowed:                   # проверяем, что доступны
    - https://www.gosuslugi.ru
    - https://online.sberbank.ru
  blocked:                   # проверяем, что НЕ доступны в режиме 3, но доступны в 1/2
    - https://www.youtube.com
    - https://twitter.com

vpn:
  interface_patterns: ["TAP", "TUN", "Wintun", "wg", "OpenVPN", "vpn"]
  exclude_interface_patterns: ["Hyper-V", "VirtualBox", "Loopback"]
  external_ip_service: "https://api.ipify.org"
  provider_ip: null          # null = автоопределение при старте; иначе строка IP провайдера

notifications:
  sound: true
  toast: true
  log_file: "monitor.log"
```

## 6. Запуск и окружение

- **A12:** автозапуск при старте Windows — через папку `shell:startup` (`.bat`/`.vbs` обёртка) или Task Scheduler. Реализуем как опцию установки.
- **A13:** Python 3.14, зависимости: `psutil` (есть), `requests` или `urllib` (stdlib), `win10toast`/`plyer` для toast, `winsound` (stdlib) для звука.
- Запуск: `python monitor.py` — работает как фоновый процесс, без GUI. Управление только через `config.yaml`.

## 7. План работ (пункты с критериями выполненности)

### П1. Конфигурация и загрузка настроек
- **Что:** модуль `config.py` — загрузка `config.yaml`, валидация, дефолты.
- **Критерий:** все поля из раздела 5 доступны через объект конфига; невалидный файл → понятная ошибка.

### П2. Проверка доступности хоста
- **Что:** `checkers.py` → `is_host_available(url, connect_timeout, read_timeout) -> bool`. HTTP GET, True если получили HTTP-ответ.
- **Критерий:** корректно distinguishes доступен/недоступен; не падает на сетевых ошибках.

### П3. Обнаружение VPN
- **Что:** `checkers.py` → `is_vpn_active(config) -> bool` по интерфейсам (psutil) + внешнему IP.
- **Критерий:** возвращает True при наличии VPN-адаптера или отличном внешнем IP.

### П4. Определение состояния за итерацию
- **Что:** `monitor.py` → `compute_state(config) -> StateEnum` по логике 3.3.
- **Критерий:** возвращает 1/2/3/4 согласно таблице состояний для заданных `allowed_ok`/`blocked_ok`/`vpn_active`.

### П5. Подтверждение смены состояния
- **Что:** класс `StateTracker` — хранит текущее подтверждённое состояние и буфер последних N наблюдений.
- **Критерий:** меняет состояние только после N одинаковых наблюдений подряд; разовые отклонения не переключают.

### П6. Уведомления
- **Что:** `notifier.py` → `notify(state_changed)` — звук (winsound) + toast (win10toast/plyer) + запись в лог.
- **Критерий:** при вызове воспроизводит звук, показывает toast, дописывает строку в `monitor.log`.

### П7. Главный цикл
- **Что:** `monitor.py` → `main()` — loop с `interval_sec`, вызывает compute_state → StateTracker → notifier.
- **Критерий:** корректно крутит цикл, останавливается по Ctrl-C, обрабатывает ошибки одной итерации (не падает весь процесс).

### П8. Автозапуск при старте Windows
- **Что:** `install_startup.py` или `.bat` в `shell:startup`.
- **Критерий:** после установки программа стартует при логине пользователя.

### П9. CLI и упаковка
- **Что:** `monitor.py --config <path>`, `--check-once` (разовая проверка, для отладки), `--install-startup` / `--uninstall-startup`.
- **Критерий:** флаги работают, `--check-once` печатает определённое состояние и выходит.

## 8. Антипаттерны / ограничения
- Не храним историю состояний (A10) — только лог переходов.
- Не управляем VPN (A2) — только определяем.
- Не различаем «VPN включён но не работает» (A4) — falls back to состояние 4.
- Тесты пишутся **до** кода (skill `tdd`), вертикальными слайсами.
